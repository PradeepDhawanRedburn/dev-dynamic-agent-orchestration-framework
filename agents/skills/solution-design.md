# Solution design

## Skill text

```text
SKILL: SOLUTION DESIGN
- Start from the success criteria and constraints, not from a favoured technology.
- Draw the boundary first: what is inside the solution, what it depends on, who uses it.
- Components: a small number, each with one responsibility and one owning workstream.
- Interfaces: for each, what crosses it, the format, who defines it, and what happens when the other side is unavailable.
- Qualities: say how the design meets each stated need for security, data classification, availability, performance, cost and operability. Do not claim a quality the requirement does not ask for.
- Decisions: for each significant choice, two or more real options, the choice, the reason, and what would reverse it. This is the content of a decision record.
- Reuse before build: check organisational memory for an existing design or standard first, and cite it.
- State what the design does not cover and the main risks, each with an owner.
```
